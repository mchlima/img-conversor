  <action>
1. Check if the Vercel CLI is installed: `npx vercel --version`. If not available, install with `npm install -g vercel`.

2. Create `vercel.json` at project root with WASM-safe CSP headers (proactively, per RESEARCH.md recommendation — cheaper to add now than debug in Phase 2). Note: script-src uses 'self' + 'wasm-unsafe-eval' only — no 'unsafe-inline' per RESEARCH.md best practice:
```json
{
  "headers": [
    {
      "source": "/(.*)",
      "headers": [
        {
          "key": "Content-Security-Policy",
          "value": "default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; style-src 'self' 'unsafe-inline'; img-src 'self' blob: data:; connect-src 'self'; worker-src 'self' blob:; font-src 'self' data:"
        }
      ]
    }
  ]
}
```

3. Deploy to Vercel:
   - If the project is connected to a git remote on GitHub, use `npx vercel --yes` for a preview deploy
   - If no git remote, use `npx vercel --yes` which will prompt for project linking
   - Capture the deploy URL from the output

4. If the deploy fails due to authentication, create a checkpoint for the user to authenticate via `npx vercel login` and retry.

5. After deploy succeeds, note the public URL for the verification checkpoint (Task 2).

NOTE: This task's automated verify only confirms vercel.json was created correctly. The actual deploy verification (INFR-03 gate) is Task 2 — the human checkpoint where the user confirms the live URL works end-to-end.
