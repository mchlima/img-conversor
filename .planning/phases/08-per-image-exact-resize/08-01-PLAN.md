  <name>Task 1: Extend ImageItem type and add store per-image resize logic</name>
  <files>types/index.ts, composables/useImageStore.ts</files>
  <read_first>types/index.ts, composables/useImageStore.ts, composables/useConvertOptions.ts</read_first>
  <action>
1. In types/index.ts, add three fields to ImageItem interface:
   - `resizeWidth: number | null` (per-image target width, null = use original)
   - `resizeHeight: number | null` (per-image target height, null = use original)
   - `resizeOverride: boolean` (true = user manually edited this card's dimensions; global propagation skips it)

2. In composables/useImageStore.ts:
   a. In addImages(), initialize new fields on each item: `resizeWidth: null, resizeHeight: null, resizeOverride: false`
   b. After createImageBitmap resolves (where originalWidth/originalHeight are set), also set `item.resizeWidth = bmp.width` and `item.resizeHeight = bmp.height` so cards start pre-filled with original dimensions (RSZN-11).
   c. Add function `updateImageResize(id: string, width: number | null, height: number | null)`:
      - Find image by id
      - Clamp width to `Math.min(width, item.originalWidth)` and height to `Math.min(height, item.originalHeight)` (RSZN-15 — never exceed original)
      - If width is null or height is null, leave that dimension unchanged
      - Set `item.resizeWidth = clampedWidth, item.resizeHeight = clampedHeight`
      - Set `item.resizeOverride = true` (RSZN-12 — marks as manually overridden)
   d. Add function `propagateGlobalResize(globalWidth: number | null, globalHeight: number | null)`:
      - Iterate all images
      - Skip any image where `item.resizeOverride === true` (RSZN-13)
      - For non-overridden images: compute clamped values per image (`Math.min(globalWidth, item.originalWidth)` etc.), set `item.resizeWidth` and `item.resizeHeight`
      - If globalWidth or globalHeight is null, set the corresponding per-image field to the image's original dimension
   e. Export `updateImageResize` and `propagateGlobalResize` from the return object.

IMPORTANT: Maintain the existing reactivity pattern — images is `useState<ImageItem[]>` and items are mutated directly (Vue 3 reactive proxy). Do NOT replace the array; mutate items in-place.
